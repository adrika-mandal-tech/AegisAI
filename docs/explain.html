System Architecture

AegisAI is split into a FastAPI backend and a Next.js 14 frontend, orchestrated locally via Docker Compose. The backend follows clean architecture with strict separation between agents, API routes, core config, evaluation, graph orchestration, LLM clients, memory, prompts, schemas, and tools.

Backend FastAPI + Python 3.12

  • agents/ — 9 standalone agents + evidence verifier + gap analyzer + chat history
  • api/ — FastAPI router with 20+ endpoints (chat, pipeline, history, documents, reports, ingestion)
  • core/ — Config, logging, constants
  • evaluation/ — DeepEval-style and RAGAS-style heuristic metrics
  • graph/ — LangGraph StateGraph pipeline, edges, nodes, SSE streaming
  • llm/ — Gemini 3.6 Flash primary, Groq fallback, auto-fallback logic
  • memory/ — Qdrant client + embedding + retrieval pipeline
  • prompts/ — Markdown system prompts with SHA-256 hashes
  • schemas/ — Pydantic contracts for requests, responses, evidence, agents
  • tools/ — Document loader, Tavily search, web scraper, MCP client, utilities
  • services/ — PDF report generation (FPDF)

Frontend Next.js 14 + React 18

  • app/ — App Router layout, main dashboard page
  • components/ — Chat, AgentTrace, ReportView, FileUpload, DocumentList, HistoryList, EvidenceLink, ToolExecutionCheckbox, EvidenceGapAnalysis
  • lib/ — API client for backend endpoints
  • hooks/ — Reusable React hooks
  • public/ — Static assets
  • SPA with 7 sections: Home, About, Docs, Pipeline, Chat, Documents, History
  • Tailwind CSS + lucide-react icons + react-markdown

Infrastructure Docker Compose

Three services defined in docker/docker-compose.yml:

  • qdrant — Vector database (ports 6333, 6334) with health checks
  • backend — FastAPI app (port 8000) depends on qdrant
  • frontend — Next.js app (port 3000) depends on backend
docker compose -f docker/docker-compose.yml up --build

Pipelines

AegisAI uses multiple coordinated pipelines to transform user queries into evidence-grounded reports.

Each node is a LangGraph state node. The shared PipelineState carries task, plan, retrieved context, research, validation, reasoning, critique, report, evidence, tool calls, memory entries, and evaluation results. Conditional edges allow routing after validation, critique, and report generation.

2. Evidence Verification Pipeline

After the main pipeline produces a response, the evidence verification pipeline extracts claims, matches them against available evidence, generates citations, and computes confidence/relevance scores. This ensures responses are grounded in retrieved or researched evidence.

3. Evidence Gap Analysis

Analyzes coverage of evidence across claims, identifies unsupported assertions, and provides recommendations for additional retrieval or research. Includes visual coverage metrics in the frontend.

4. Chat History Pipeline

Persistent conversation storage with CRUD operations, search, export/import. Managed by ChatHistoryManager with in-memory storage (extendable to persistent DB).

5. Ingestion Pipelines

Multi-format document ingestion (PDF, DOCX, XLS, XLSX, TXT, MD, CSV, ZIP) via Docling and custom loaders. URL ingestion and GitHub repo ingestion pipelines parse content, chunk it, embed it, and upsert into Qdrant.

6. PDF Report Pipeline

Generates branded PDF reports from Markdown with table of contents, heading hierarchy, body content, and "Aegis AI" watermark using FPDF.

Features

Multi-Agent Orchestration

9 specialized agents (Supervisor, Planner, Retriever, Researcher, Validator, Reasoner, Critic, ReportGenerator, ToolAgent + Memory) execute in a strict sequential LangGraph workflow with conditional branching.

Conversational Chat

Chat interface with conversation history, evidence display, citations, confidence scores, plan preview, and tool execution settings toggle.

Document Intelligence

Upload PDF, DOC, DOCX, XLS, XLSX, TXT, MD, CSV, ZIP. Documents are parsed with Docling or custom loaders, chunked, embedded, and stored in Qdrant for semantic retrieval.

Streaming Pipeline

Real-time SSE streaming of agent events (agent_start, agent_output, agent_complete, pipeline_complete, error) via GET /api/pipeline/stream.

Evaluation Metrics

DeepEval-style report quality scoring and RAGAS-style RAG faithfulness scoring run after every pipeline. Metrics include readability, structure, completeness, citation density, context relevance, and pipeline efficiency.

Evidence & Citations

Evidence verification pipeline extracts claims, matches evidence, generates citations, and computes confidence/relevance. Evidence gap analysis identifies unsupported claims.

PDF Reports

Generate branded PDF reports with table of contents, heading hierarchy, body content, and watermark using FPDF.

URL & Repo Ingestion

Ingest content from URLs and GitHub repositories. Parse, chunk, embed, and index into Qdrant for retrieval.

Chat History

Persistent conversation history with CRUD, search, export/import. Manage multiple sessions and resumes.

Limitations

Current Constraints

  • No live deployment: Application runs locally only; no public URL.
  • In-memory stores: Document registry, pipeline history, and chat history are in-memory and lost on restart unless persisted via Docker volumes.
  • Dry-run mode: Without API keys, agents return empty/dry-run results.
  • Single LLM primary: Default is Gemini 3.6 Flash; Groq is fallback only.
  • Sequential execution: Pipeline runs agents sequentially; no parallel execution of independent branches.
  • Heuristic evaluation: DeepEval and RAGAS metrics are heuristic-based; full framework integration requires additional packages.
  • No authentication: No user accounts, roles, or API key management for end users.
  • Local file storage: Uploaded documents stored locally; no S3 or cloud storage integration.

Technical Debt & Trade-offs

  • No LangChain dependency (by design) — some ecosystem integrations require custom wrappers.
  • Evidence matching is heuristic-based; not a full NLI/claim verification model.
  • Qdrant is the only vector store; no abstraction for swapping backends.
  • Frontend is a single-page app; routing is client-side state-based, not URL-based.
  • No automated CI/CD pipeline configured.

Advantages

Modular & Testable

Every agent is standalone with its own API endpoint. Clean architecture enables unit testing, isolated development, and easy replacement of components.

Transparent Pipeline

LangGraph provides explicit, debuggable workflow. SSE streaming shows real-time agent execution. No hidden "black box" reasoning.

Evidence-Grounded

Responses are linked to retrieved evidence with citations, confidence scores, and gap analysis. Reduces hallucination risk.

Built-in Evaluation

DeepEval and RAGAS metrics run automatically after every pipeline, providing continuous quality feedback without external tooling.

Type Safety

End-to-end Pydantic schemas ensure request/response contracts are validated. Mypy strict mode catches type errors early.

Local-First

Runs fully locally with Docker Compose. No mandatory cloud dependencies. Dry-run mode allows development without API keys.

Modern Stack

FastAPI, Next.js 14, Tailwind CSS, LangGraph, Qdrant — all modern, well-maintained libraries with active communities.

Extensible

Add new agents by implementing the agent interface and registering in the graph. Swap LLM providers via factory pattern. Add tools via the tools module.

Production-Ready Patterns

Structured logging, graceful fallbacks, CORS hardening, health checks, request correlation IDs, and typed envelopes.

Database & Tools

Primary Database

Qdrant — Vector database for semantic retrieval.

  • Stores embedded document chunks and memory entries
  • Cosine distance metric
  • Collection: aegisai
  • Ports: 6333 (HTTP), 6334 (gRPC)
  • Docker volume: qdrant_data
  • Client: qdrant-client Python SDK

Embeddings

Embeddings are generated via the configured LLM provider (Google GenAI by default) or compatible embedding models. The system uses Hugging Face's transformers library and sentence-transformers models, with the Hugging Face API key enabling access to their hosted inference API for embedding generation. Local FastEmbed fallback is available for offline operation. Vectors are upserted into Qdrant for similarity search.

Live Frontend URL

No live deployment is currently configured. AegisAI is designed for local development only. The frontend runs at http://localhost:3000 and the backend at http://localhost:8000 when started locally or via Docker Compose.

To deploy publicly, you would need to:

  • Push the repository to GitHub
  • Connect the frontend to Vercel, Render, or Fly.io
  • Deploy the backend to a container service (Render, Fly.io, AWS ECS, etc.)
  • Use a managed Qdrant instance or cloud vector database
  • Set production environment variables for API keys and database URLs
